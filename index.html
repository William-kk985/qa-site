        上传一个 .wasm、.js 或 .py，用它替换站点里的外观或排序算法。
        只存在你自己这个浏览器里，别人拿不到、也影响不到别人；「一键还原」会一并清掉。
      


      

        三个能力，随便实现几个（没实现的用站点默认）：

        · theme(i) → number —— 第 i 个外观槽位的值，返回负数 = 这个槽位用站点默认

        · hot_score(点赞, 回答, 浏览, 距今天数) → number —— 替换「热门」排序的打分

        · search_score(query, text) → number —— 搜索时决定谁排前面
        （只排序，不过滤：写坏了最坏是顺序难看，不会让结果消失）

        前两个是纯数字，任何语言都能写。search_score
        要吃字符串：JS / TypeScript / ReScript / Python 直接写就行；wasm（C / C++ / Rust）
        要多导出一个 qa_buffer() 走内存协议；MoonBit 要额外配
        export-memory-name + inline wasm（也做到了）。
        细节见 plugins/README.md。
      


      

        三种后端，ABI 一样

        · .wasm —— 能编 wasm 的语言：MoonBit / C / C++ / Rust / Zig…

          跑在 wasm 沙箱里、零外部依赖，碰不到页面。

        · .js —— 只能编 JS 的语言：TypeScript / ReScript / 手写 JS

          （tsc → .js，ReScript → .mjs，把编译产物传上来就行）

          ⚠️ JS 是跑在页面里的，权限比 wasm 大得多 ——
        只传你自己写的 / 自己编译的，别把别人发你的 .js 传进来。

        · .py —— Python。和其它语言不一样，见下。
      


      

        ⚠️ 用 Python 之前先看这条

        Python 没法像别的语言那样编成一个几百字节的产物 —— 它的运行时本身就是
        一大坨 wasm（Pyodide：核心 9.6MB + 标准库 2.2MB ≈ 12MB）。

        所以：你上传的只是 .py 源码（几百字节，照旧只存在你自己浏览器里），
        运行时只在你真的用了 Python 插件时才去 CDN 拉一次（之后浏览器会缓存）。

        没装 Python 插件的人一个字节都不会下载。

        代价：第一次用要等十几秒 + 十几 MB 流量，而且要能连上 CDN。
        只是想改个颜色的话，用别的语言或直接写自定义 CSS 划算得多。
